# Hosted market workspace

The current application is **Predictir** at https://predictir.dev. Vercel serves the Next.js interface and an authenticated proxy. Railway maintains the exchange WebSocket, shared caches and ingestion worker. Supabase in US East (Ohio) stores typed observations, private journal records and compressed evidence objects.

## Reproduce

Use Node 26.12.1 and `npm ci` in `web/`. Run `npm test`, `npm run typecheck` and `npm run build`. For actual Postgres integration checks, set `MARKET_TEST_DATABASE_URL` to a disposable database whose name ends in `_test`. `node tests/verify-sports-live.mjs` retrieves the public schedules again; results will change as games and source corrections arrive. `node tools/benchmark_books.mjs` reproduces the local indexed-book comparison.

Preview numbered SQL migrations with `DATABASE_URL` and `DATABASE_CA_CERT` set, using `node tools/migrate.mjs`; apply the reviewed additive plan explicitly with `node tools/migrate.mjs --apply`. Applied-file hashes and a migration lock detect drift and competing changes. Hosted runtime credentials use a separate login with access only to the `market_lab` schema, statement timeouts and a small connection pool. The backend account cannot migrate the database. Application tables have RLS and no anonymous policies. The schema is not exposed through the public Data API.

The existing `market_lab_app` login has a **12-connection** limit. Each backend process uses a pool of at most four connections plus one dedicated job-notification connection. Two processes can overlap during a rolling replacement, so the budget is `2 × (4 + 1) + 2` operational runtime connections. An administrator provisioning this existing login sets `ALTER ROLE market_lab_app CONNECTION LIMIT 12;`; this changes no grants or RLS behavior. Keep the deployment at one steady replica and recalculate this budget before adding replicas or a second pooler mode. The current database permits 60 total connections; Supabase services also consume that total.

The deployed runtime uses shared Supavisor session mode on port 5432. Its effective project pool ceiling is 15, with 200 client slots and a 600-second server-idle setting, as read on November 5, 2026. The pool grows on demand rather than allocating its ceiling immediately. The narrower role limit supports the application's bounded rolling demand. Two consecutive six-client, read-only probes succeeded after the limit correction; the second reused the same eleven database backends without opening more. No project pool setting or compute tier changed. [Supabase pooling terminology](https://supabase.com/kb/troubleshooting/supavisor-and-connection-terminology-explained-9pr_ZO) and [Supavisor FAQ](https://supabase.com/kb/troubleshooting/supavisor-faq-YyP5tI).

Supabase's official CA is supplied through `DATABASE_CA_CERT`; certificate and hostname verification remain enabled. Download the CA from the project's Database Settings. The CA used on November 4, 2026 has SHA-256 fingerprint `80:70:25:AD:50:D4:ED:21:9D:2C:9C:7D:29:9C:00:4F:82:4E:B0:0C:F7:F6:5A:FE:F6:07:D0:7B:72:E6:CA:FA`.

There is no `NEXT_PUBLIC_API_URL` requirement: the browser calls the same-origin API and Vercel proxies to Railway. Gateway authentication uses Vercel's deployment OIDC token. The verified available explanation model is `google/gemini-2.5-flash-lite`. Statistical estimates are calculated by the research service, not by the language model.

Railway needs the same two application secrets; backend-only `DATABASE_URL`, `DATABASE_CA_CERT`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`; optional Kalshi streaming credentials, Spotify client credentials and X bearer token. Never use a `NEXT_PUBLIC_` prefix for credentials. A Supabase management access token is a setup credential and is not installed in either runtime. `PORT=8780` starts the backend; `MARKET_PIPELINE_ENABLED=1` enables the durable jobs.

Railway's deployment health check is `/api/health` with a 120-second startup timeout. The existing service is not linked to the legacy `railway.toml`: Railway now rejects new links to that format. The checked-in file records the older deployment intent. A future native IaC migration must preserve the existing service and unmanaged secrets. Existing links to legacy TOML/JSON configuration stop working on December 1, 2026. [Migration guide](https://docs.railway.com/infrastructure-as-code).

The GitHub source deploys `main` with root `/web` and the `Dockerfile` in that build context. The live watch pattern `/web/**` uses repository-relative paths. Web checks build and start the same Node 26.12.1 backend image on application changes, in addition to application tests and the Next.js build. Run `node tools/reconcile_railway.mjs` from `web/` with the authenticated Railway CLI to preview the existing service's watch pattern and restart retry count. The private evidence bucket is `market-lab-evidence`. No public object policy exists. Archives use immutable content hashes and gzip; cache hits preserve original source retrieval timestamps. The worker uses unique scheduled keys, transactional claims, leases, retries with backoff and idempotent dataset publication. Completion requires ownership of the unexpired claim. Failed jobs remain inspectable.

## Cost controls

The app limits global and per-visitor work, streaming slots, body sizes, source queues and paid reads. The assistant conservatively reserves $0.025 before a request against a $3 monthly allowance and allows at most 20 requests per visitor daily. Completed metered requests settle that reservation once using reported token counts, dated model prices and a 25% cushion; duplicate settlements cannot create extra allowance. Failed/unmetered calls retain the reservation. A separate native AI Gateway project budget also limits model spending to $3 monthly. X reserves at most 1,000 post reads per month (about $5 at the checked resource price, plus bounded cached user lookups). Evidence compression has a 1 GB monthly write allowance. Realtime reserves egress in batches against 60 GB/month, approximately $3 at the checked Railway egress rate, and 18,000 stream-minutes. Private diagnostics report allowance use. Allowances fail closed on storage outages.

Vercel has a $5 additional metered-usage budget with automatic production pause; provider checks are periodic. Supabase's included-usage Spend Cap is enabled and automatic preview database branching is disabled. Compute and other opted-in add-ons are outside that cap. After the owner upgraded Railway to Hobby, its workspace hard usage limit was set to $10 and read back successfully on November 5, 2026 UTC. This is a workspace limit, including any other projects in that workspace. No new paid add-ons or automatic credit top-ups were purchased during this repair.

## Access and telemetry

The active Vercel firewall denies CN, IN, RU, BY, UA, MD, EE, LV, LT, AM, AZ, GE, KZ, KG, TJ, TM, UZ, AL, BA, BG, HR, GR, XK, ME, MK, RO, RS, SI, CZ, HU, PL and SK. This makes the requested former Soviet, Balkan and Eastern European scope explicit. It controls IP-geolocated visitor access; the database is hosted in the United States. The backend requires the private proxy secret and rejects untrusted/unknown country headers, preventing direct Railway URL access from bypassing the application restriction. MCP and internal budget routes require a separate service credential.

The API firewall limits 120 requests per minute per IP. The backend also enforces global and visitor limits, caps active streams, bounds payloads and rejects redirected or HTML data responses. Database queries use bound parameters. Source URLs are allowlisted. The MCP service exposes only bounded public-data reads for the selected contract. Neither the assistant nor Analytics receives private journal tokens, chat transcripts as telemetry, bankroll entries or provider credentials.

The existing Vercel project has Fluid Compute enabled. Its API function allows 800 seconds; event streams connect within five seconds and rotate cleanly after at most 750 seconds, before either the function limit or the backend's 840-second stream limit. This replaces the previous abrupt 55-second fetch abort. JSON requests retain their existing deadlines. The relay propagates cancellation, bounds buffered chunks and cancels upstream reads on completion. These limits do not remove application work, streaming, egress or spending quotas. [Vercel duration and I/O billing](https://vercel.com/docs/functions/configuring-functions/duration).

The published GTM container serves HTTP 200 and contains that measurement destination. `predictir.dev` is explicitly included in its monitored domains. The app loads the tag after consent, excludes advertising signals, strips query strings and fragments, and sends only public market/category interactions. Analytics settings allow revocation. Do not remove consent checks to silence that diagnostic.

Importing a journal access token does not copy historical AWS records into Supabase. No historical prediction is backfilled or silently scored as prospective.
